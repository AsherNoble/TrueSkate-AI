# M1-MULTITAP8-20260925 — Eight-touch limit probe

Status: three bounded XR2 recordings saved; five of eight requested positions
brightened in each. Operator frame review is available in the viewer. No
training data or calibration method was adopted.

## Published evidence and code inspection

[Unity's iOS input documentation](https://docs.unity3d.com/2018.3/Documentation/Manual/MobileInput.html)
says iPhones can track up to five concurrent fingers. [Apple's XR
specifications](https://support.apple.com/kb/SP781) call the display Multi-Touch
but do not state a finger count. [Appium's input-events
guide](https://github.com/appium/appium-xcuitest-driver/blob/master/docs/guides/input-events.md)
describes how separate XCTest pointer-event paths form a multitouch action;
it also notes that this private API has limited documentation. The literature
therefore supports a five-contact hypothesis, but does not by itself prove
the limit of this exact XR/WDA/True Skate path.

The local payload test confirms eight unique pointer sources and all eight
`pointerDown` actions at the same W3C tick. The deployed WDA fork at
`b5ace217` loops over all submitted action IDs and adds every resulting path
to `XCSynthesizedEventRecord` in `FBW3CActionsSynthesizer.m`. No five-source
truncation was found in the sender or this WDA construction loop. The private
XCTest execution, iOS touch delivery, and True Skate's handling remain
possible limiting layers.

## Device test

The eight positions form a 4 × 2 grid with 66-point spacing: x = 108, 174,
240, 306 and y = 415, 481 logical points. The middle four are the exact
points from the successful four-touch probe. All pass the control hitbox
check. Three isolated recordings used the same spatial grid with row-major,
reverse, and column-major pointer-source order respectively. No single-touch
control was recorded; reset occurred before each recording.

All three commands returned success in 2.99, 2.87, and 3.16 s, and True Skate
remained in gameplay. An exploratory full-video brightness check found exactly
five visibly brightened requested positions in **each** recording. The subset
changed with pointer order. This agrees with the [91-touch
probe](M1-MULTITAP91-20260925.md), which also yielded five visible positions
per recording. It is strong evidence for a five-contact practical limit in
this path, though it cannot isolate which downstream layer enforces it. The
check's scores and detected positions are in
[visual-check.json](../evidence/M1-MULTITAP8-20260925/visual-check.json).
