# M1-ENDPROBE-20260930 — Is the end-point shortfall made by the decoder?

Status: preregistered (2026-09-30), operator-approved. Validation only;
≈ $0.5 of Modal time; no training.

## Question

Most remaining failures are end points that stop short along the correct path
(140/145 end misses at 64×144, [M1-HALFRES](M1-HALFRES-20260928.md)). The
labels are right in 28/30 reviewed misses ([M1-DIAG](M1-DIAG-20260928.md)),
and neither resolution direction fixed the Kansas City and Los Angeles misses.

`BasicLinearRegressor` reads the end point with **one softmax over every pixel
of every frame**, weighted by a Gaussian time prior. The prior is centred on a
liftoff estimated from the model's own predicted duration
(`0.24 + duration / 2.27`) and is wide (σ = 0.15 of the clip, ≈ 0.34 s).
Before liftoff the trail has not reached its tip, so weight on those frames
pulls the soft-argmax short. Is that mechanism what costs recovery?

## Prior work (not repeated)

In August, on the old 80% model, EQ-001/002/009 fitted a single post-hoc
along-path shift. It was inconclusive (a 3-clip effect). EQ-004 tested the
line-fit decoder, which also came out inconclusive. None of these changed the
time window the end is read from, and none ran on the clean-label models.

## Method

Checkpoints: the three current-recipe models
`basic_linear_good13100_halfres_cosine_seed{0,1,2}.pth` (64×144, cosine). One
decode pass over the fixed 1,965-clip validation partition. The score maps are
held fixed, and only the end read-out changes. Start and duration stay the
model's own, so recovery changes only through the end point.

| Variant | Time-window centre | σ | Inference-feasible |
|---|---|---:|---|
| `baseline` | predicted liftoff | 0.15 | yes (must reproduce the model; drift > 1e-4 aborts) |
| `sigma_0.075` | predicted liftoff | 0.075 | yes |
| `sigma_0.05` | predicted liftoff | 0.05 | yes |
| `oracle_liftoff` | true liftoff | 0.15 | no (diagnostic) |
| `oracle_liftoff_sigma_0.05` | true liftoff | 0.05 | no |
| `oracle_frame` | the single frame nearest true liftoff (spatial read only) | — | no |

Also recorded per clip: the attention-weighted time of the baseline read, the
predicted and true liftoff, and the signed along-path end error.

Code: `src/trueskate_ai/model1/linear/end_probe.py` and the Modal entry point
`probe_end_decoding` (unit-tested; the test partition is never loaded).

## Decision rules (fixed before running)

Every Δ below is the three-seed mean change in validation recovery against
`baseline`.

1. **Liftoff timing (H1):** `oracle_liftoff` Δ ≥ +2 pp → a wrong time-window
   centre is a material cause. Next: a training experiment to improve liftoff
   estimation. Δ < +0.5 pp → the centre is not the cause.
2. **Temporal averaging (H2):** the better of `sigma_0.075` / `sigma_0.05`
   has Δ ≥ +1 pp → averaging over time costs accuracy even with the model's
   own timing. Next: a retrain with a narrower window. σ is chosen on
   validation here, so adoption needs a retrain and a fresh evaluation.
3. **Weak tip response (H3):** if `oracle_frame` still leaves ≥ 70% of the
   baseline's end-short failures, then even the right frame read spatially
   stops short. The tip response itself is weak, so the fix lies in features
   or supervision, not aggregation.

**Descriptive:** among baseline end-short failures, the fraction whose
attention time is earlier than the true liftoff, and the predicted-duration
error for end-short failures against successes.

**Caveat:** the frozen maps were trained under the σ = 0.15 read and may have
adapted to it. A frozen intervention can therefore understate what a retrain
would gain. A null result in H1/H2 is weaker evidence than a positive one.

## Result (2026-09-30)

Code `0f9ecad`, L4, ≈ 15 min (≈ $0.3). `max_baseline_drift` = 0.0, and the
baseline reproduces each checkpoint's train-time validation exactly (89.92 /
88.19 / 90.08%). Test partition untouched.
[Summary](../evidence/M1-ENDPROBE-20260930/summary.json),
[analysis](../evidence/M1-ENDPROBE-20260930/analysis.txt). The full per-clip
file is on the `trueskate-models` volume
(`basic_linear_endprobe_validation_cosine_seeds012.json`).

| Variant | Seed 0 / 1 / 2 | **Mean** | Δ | End-short failures (3 seeds) |
|---|---|---:|---:|---:|
| `baseline` | 89.92 / 88.19 / 90.08 | **89.40%** | — | 452 |
| `oracle_liftoff` | 89.82 / 88.14 / 90.18 | 89.38% | −0.02 | 449 |
| `sigma_0.075` | 90.89 / 88.91 / 90.79 | 90.20% | +0.80 | 403 |
| `sigma_0.05` | 91.25 / 89.21 / 90.99 | **90.48%** | **+1.09** | 382 |
| `oracle_liftoff_sigma_0.05` | 91.30 / 89.11 / 91.20 | 90.53% | +1.14 | 367 |
| `oracle_frame` | 38.68 / 88.60 / 52.32 | 59.86% | −29.53 | 1,839 |

**H1, liftoff timing: not the cause.** The true liftoff changes nothing
(−0.02 pp). The duration estimate is already accurate, even on failures
(median error −0.007 to −0.014 s against a 0.10 s tolerance).

**H2, temporal averaging: confirmed.** σ = 0.05 gains +1.09 pp (+1.33, +1.02
and +0.91 per seed). The paired change is one-sided: 28 / 21 / 19 clips gained
against 2 / 1 / 1 lost, McNemar p ≤ 4e-5 for every seed. End-short failures
fall 15% (452 → 382). By the fixed rule, **next is a retrain with a narrower
end window.** σ was picked on validation from two values, but the effect is
monotone (0.15 → 0.075 → 0.05) and nearly lossless, so the selection effect is
small.

**H3, weak tip response: the test is invalid, so no conclusion.** The
single-frame read meets the rule's literal condition (1,839 short failures
against 452). But it also breaks 1,027 and 760 clips that seeds 0 and 2
already recovered, while seed 1 is unchanged (88.60%). The frozen maps were
never trained to be read one frame at a time, and seeds learned different
per-frame behaviour. The variant measures a read-out mismatch, not the
strength of the tip response.

**Descriptive:**
- Attention is centred before the true liftoff for 76–95% of end-short
  failures (median −0.05 to −0.14 s), and also for most successes (median
  −0.004 to −0.075 s).
- Failures are shorter, faster gestures: median duration 0.56–0.60 s against
  0.77 s for successes.

**What it explains:** averaging over time accounts for a minority of the
shortfall. 382 of 452 end-short failures (85%) remain at σ = 0.05, with a
median shortfall of 0.054–0.071, about twice the tolerance. The rest is
unexplained. A plausible, untested lead is temporal resolution: 32 frames
over 2.27 s is ~71 ms per frame, so a 0.58 s gesture spans ~8 frames, and the
tip moves far between frames.

## Next (operator decision)

Retrain with the end window narrowed during training: make σ a training
setting (it is hardcoded at 0.15) and set it to 0.05; 64×144, cosine, seeds
0–2, ≈ $6. The maps would adapt to the narrow read, which the frozen test
cannot show. Rule, fixed before launch: adopt if the three-seed last-10 mean
is ≥ 90.17% (the cosine 89.17% + 1 pp).
