# M1-COLAB-20261006 — One Model 1 seed on free Colab against Modal

Status: **stopped, incomplete** (19 of 40 epochs). Predeclared 2026-10-06; run
2026-10-12; stopped by the operator on 2026-10-13 after Colab ended the
second session. See [Results](#results).

## Question

Can free Colab train one current Model 1 seed in place of Modal, and at what
cost in time, recovery and operator effort? One account, one runtime at a time,
no paid compute. A successful run would justify **researching** parallel
execution; this experiment draws no parallel-reliability or monthly-capacity
conclusion.

## Reference

[M1-EXPAND-20260929](M1-EXPAND-20260929.md) seed 0 on Modal L4
(`expand20260930_cosine_seed0`, checkpoint SHA-256 `e5ccb3fe…`):

- 3.12–3.19 h per seed. The first epoch took 918 s, including filling the
  decoded-frame cache; later epochs took about 267 s.
- About US$4.15 per seed (US$12.46 for three).
- Last-10-epoch validation mean **90.92%**; best 91.25% at epoch 39.

No new Modal job is launched; the history and checkpoint were exported read-only.

## Fixed design

- **Source:** `e0424f99e3f668e1722e56fac4f17372cd60a62d`, checksum-locked
  file by file ([input lock](../evidence/M1-COLAB-20261006/input-lock.json)).
- **Data:** experiment `model1_expand_20260930` (fingerprint
  `sha256:82e323f9…`). Train 18,394; validation 1,965; test 1,965 (not
  scored). Sealed shards `sha256:85e6a844…`: the sealed manifest lists
  **44 shards** (1.16 GB, 22,324 samples). The M1-EXPAND note's "46" was
  approximate.
- **Recipe:** unchanged from the reference. Seed 0 and split seed 0; 40 epochs;
  cosine schedule; AdamW at 1e-3; batch 8; 64×144 input; 32 frames; 16 base
  channels; temporal mixer; sequential decode; full precision; manifest
  content verification on.
- **One deliberate difference:** decoded-frame caching is **off**. The cache
  needs about 17 GiB, and free Colab has about 12.7 GB of RAM. The trainer
  decodes in its main process, so every Colab epoch pays the decode cost that
  Modal paid once.
- **Environment:** Python 3.11 in a runtime-local `.venv` with the original
  pins: torch 2.12.0 (`+cu130`), opencv-python-headless 4.13.0.92,
  numpy 2.4.6, scipy 1.17.1, selenium 4.43.0. GPU, driver, CUDA, cuDNN and
  thread counts are recorded per session. If the pins cannot run, report
  incompatibility; never substitute packages.
- **Not evaluated:** test, training-set and new-park holdout partitions.

## Budget and attempt rules

- **12 cumulative GPU-allocation hours within 72 calendar hours** of the first
  allocation. This includes setup, diagnostics, staging, idle time, recovery and
  interrupted work.
- An allocation is charged from VM boot. It is closed only after deletion is
  observed in Runtime → Manage sessions.
- **At most two connection attempts per UTC day.** No automatic reconnects,
  retries or keep-alives. Failed GPU connections count as attempts.
- On budget expiry the harness kills training, preserves the last verified
  checkpoint and releases the runtime.

## Sequence

1. **CPU preparation:** verify the uploaded bundle, publish the allowlisted
   inputs to private Drive, and record the first attempt.
2. **Timing (free T4):**
   - Pinned install, environment record, then staging from Drive to local disk
     with full content verification.
   - **Preflight:** a real training batch must give a finite loss and
     gradients. Then score the Modal seed-0 checkpoint once on validation.
     **Stop with an environment-mismatch finding if recovery differs by more
     than 0.5 percentage points.**
   - Run epochs 1–5 of the unchanged 40-epoch schedule. After every epoch,
     copy the complete checkpoint to Drive and verify its checksum.
3. **Recovery:** stop deliberately after epoch 5, then delete the runtime and
   observe the deletion.
4. **Completion (new free T4):** recreate the environment and data, then resume
   at epoch 6. At the first resumed epoch the harness compares digests of the
   restored model, optimizer, shuffle generator and Torch, NumPy and CUDA RNG
   states against the epoch-5 snapshot. It also checks the resumed cosine
   learning rate. Then it continues toward epoch 40.
5. **Interruptions:** resume from the last verified checkpoint within the
   remaining budget and daily attempt cap.

## Deviation: scoped storage (2026-10-12, before any GPU allocation)

**Change:** Drive access moves from Colab's `drive.mount` to rclone with
Google's `drive.file` scope and the operator's own OAuth client.

- **Reach:** the credential sees only files that client created.
  `root_folder_id` pins it to one new benchmark folder. It cannot list or read
  any other Drive file.
- **Delivery:** the credential is a Colab secret granted to this notebook only.
  Every cell refuses a config without `scope = drive.file` and a
  `root_folder_id`.
- **Harness:** persistent state is a local mirror on the Colab machine.
  `persist` uploads each file and compares Drive's own SHA-256 before anything
  that depends on it is written; a checkpoint is verified before `latest.json`
  names it.
- **Inputs:** they are re-uploaded from the operator's Mac into the new folder,
  then verified by Drive checksums against the unchanged input lock before any
  attempt is recorded. The first upload, to a user-created folder, is invisible
  to this credential.
- **Unchanged:** the experiment design, recipe, budget, gates and
  classification. Staging time on Colab now includes pulling the inputs from
  the scoped folder; it is reported separately as `inputs_pull_seconds`.

### Setup as executed (2026-10-12)

- **Authorization:** Google's token information endpoint reported the granted
  scope as exactly `https://www.googleapis.com/auth/drive.file`. Before the
  folder existed, the credential listed nothing in a Drive holding 58 GB.
  Enabling the Drive API on the new project took one extra operator click.
  A `rclone config update` re-ran the consent flow once; the token stayed
  `drive.file`.
- **Upload:** the harness, the four locked inputs and the notebook went from
  the Mac to the scoped folder at about 6 MiB/s. Drive's SHA-256 values matched
  the input lock for all four inputs.
- **Bootstrap fix:** the first step-1 run failed before the harness loaded.
  `downloads.rclone.org` returns HTTP 403 to urllib's default User-Agent. The
  bootstrap now fetches the same pinned zip from rclone's GitHub release, and
  the SHA-256 pin `982b5aa7…` is still enforced. The notebook is now
  `276151ee…`; the harness files are unchanged. No attempt was recorded and no
  GPU was allocated before the fix.
- **Colab kernel:** the kernel is now Python 3.13. The harness still builds
  its own Python 3.11.17 environment with `torch 2.12.0+cu130`, as recorded in
  each session's `environment.json`.
- **Runtime type:** saving T4 in "Change runtime type" connects a GPU at once.
  That connection is the prepared attempt, and allocation is charged from VM
  boot, which is earlier.

  - a Screen Sharing sign-in on the rig;

  US$4.15. No saving is assigned to partial work.

### Reading

- The free T4 reproduced the reference environment and the training
  trajectory.
- One seed would need about 10.5 h of uncached training. That is more than the
  4.15 h that session survived, so a seed spans at least three sessions, each
  with about 10 minutes of setup. With two attempts per UTC day, that adds
  calendar days.
- Uncached free Colab cannot replace Modal for a 3-seed batch on turnaround. It
  can for cash cost, if the operator accepts multi-day runs.
- A compressed frame cache (estimated 4–6.5 h per seed) is the change most
  likely to make a seed fit one session. It is a follow-up and was not tested
  here.
