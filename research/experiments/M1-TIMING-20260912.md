## Calibration search failure

In 073122 the automated calibration reported offsets +3.9 and +1.7 s and
rejected their disagreement. Human calibration onsets are instead near -0.63 s.

touches. This is a concrete failure of its time-reference/search assumption.

established; the current code and saved rejection records support the diagnosis.
No fix has yet been implemented or validated.

### Canonical linear collection integration (2026-09-13)

The user accepted run10's approximately one-frame variation as sufficient for
the finite-slope linear collection stage and selected the WDA submission clock
with first/last visible anchors as canonical. The collector now requires the
exact instrumented WDA revision for `--basic-linears`, captures and validates
every action record, and reserves the end of each one-minute segment for its
second anchor. Both 50 ms controls use the exact normalised screen centre
`[0.5, 0.5]`, avoiding the observed moving red-floor detector edge case.

The aligner uses the V2 local-background detector on those controls and fits
`video_time = intercept + rate * submitted_to_ios.monotonic_s`. It fails closed
for missing/mismatched WDA reports, missing anchors, implausible clock rate,
short anchor span, or a control onset inside a payload clip. Controls remain in
the raw manifest but are explicitly skipped during sample creation. The linear
wrapper disables in-recording resets; its only reset occurs before recording
and after a 1.5 s clear interval. Offline unit and integration tests cover the
new contracts. No phone collection was run as part of this implementation.
