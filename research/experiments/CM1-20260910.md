# CM1-20260910 — Classical linear trace recovery

Status: in progress. Local-only R&D; no device operations or paid compute.

## Comparison contract

Target: the 1,965-command test partition behind M1-20260904's 80.05089%.
The existing Modal corpus `trueskate-corpus-v2/model1_linear_20260902`
contains 13,100 metadata paths. Prefixing their sorted sample paths with
`/corpus/` reproduces the original checkpoint's dataset fingerprint exactly:
`sha256:13100:73d7b1c7046cbe870a36b42ee756c300f4293584b434dcd448ce4a142f7a3588`.
The historical fingerprint proves path membership, not historical video bytes.
Local manifests additionally hash present metadata and video contents.

Use the original command split, seed 0, and 32 BGR frames resized to 128×288.
Predictor inputs exclude command labels and absolute touch-relative time.
All clips count: start/end Euclidean normalized error <=0.03 AND duration error
<=0.10 seconds. Missing detections fail. Tune only on training/validation.

## Initial hypothesis

Colour/background changes isolate the orange trace. Continuous components
approximate its moving position; temporal movement separates active movement
from the stationary fading trail. Compare component centroid with leading tip,
then diagnose failure categories before modifying the algorithm.

## Reproduction

From the feature worktree, use the original repository's `.venv/bin/python`
with `PYTHONPATH=src`. `scripts/model1/classical_model1.py` provides `prepare`,
`evaluate`, and `freeze`; `scripts/model1/classical_loop.py` runs a bounded
JSON-defined candidate batch and saves its resume command after each candidate.
Runtime artifacts are in the original checkout's `tmp/classical-model-1/`.
The test path refuses an unverified corpus, requires frozen source/configuration,
and binds resumption to the same final-test run identifier.

## Resource and stopping rules

Two local workers, one OpenCV thread each, one clip at a time. No full-frame
corpus cache. Six-hour active-work ceiling across resumed sessions. Reserve the
last hour for verification/reporting; stop earlier after three unsuccessful
hypothesis rounds. Usage-limit resets do not themselves restart an agent.

No curves, spin, live collection, overlay viewer, Model 2 changes or deployment.

## Data decoding finding

The first 256 training samples all reported 31 container frames against 32
metadata timestamps. A strict equality check rejected them before prediction;
that run is a loader diagnostic, not a 0% algorithm result. A sequential decode
spot check also differed between local OpenCV and FFmpeg. For comparability,
the experiment now calls the unchanged historical `_decode_even_frames` loader
and records the container/metadata counts in each prediction. The same 32-frame
neural input convention is preserved; no collection admission rule is changed.
The historical command grouping/split implementation at `8277414` matches current
code. Manifest partitions are 9,170 / 1,965 / 1,965, with content hashes sealed.

## Rounds

- R1: 256 fixed training clips; centroid baseline 36/256 (14.06%). Leading tip
  21/256; stricter motion threshold 25/256; combined 17/256. Nine detections
  missing in each arm. First extraction/evaluation 19.46 s, peak process RSS
  about 218 MiB; cached geometry variants under one second. These are training
  measurements, not validation or final test performance.
- Failure inspection: large orange scenery components follow camera movement
  and win the displacement-based track selection. R2 therefore tests finite,
  bright, approximately constant-velocity tracks, then candidate coverage and
  pale-core saturation. This is an evidence-driven change in track selection.
- R2: finite-track scoring 48/256 (18.75%); retaining 15 components alone did
  not help. Including the pale trace core (minimum saturation 35 rather than
  80) reached 82/256 (32.03%). Leading-tip geometry remained worse (31/256).
  Among 138 predictions with both endpoint errors below 0.10, median signed
  along-path error was +0.0126 at start and -0.0190 at end: the estimated path
  is systematically too short. Median signed duration error was +0.0156 s.
- R3 hypothesis: bright pale pixels distinguish the luminous trace from
  saturated orange scenery. Compare higher brightness and upper saturation
  bounds before testing the observed endpoint-shortening correction.
- R3 rejected: brightness floors 170/210 increased missing detections to
  51–81/256 and reduced recovery to 9.77–20.31%. Keep the lower brightness floor.
- R4: extending both endpoints by 0.02 normalized distance along the inferred
  direction improved recovery to 103/256 (40.23%); subtracting 0.02 s from
  duration gave 105/256 (41.02%). The uncorrected baseline remained 82/256.
  This training-selected configuration was promoted to full validation.
- R5: test a bounded deterministic straight-motion consensus across component
  candidates from the entire clip. Hypothesis: greedy frame-to-frame association
  switches from the trace onto unrelated scenery. Compare with/without R4's
  endpoint/duration correction. No test partition exposure.
- R4 full validation: **871/1,965 (44.33%)**, 18 missing detections. Wall time
  271.50 s while sharing CPU with probes; peak RSS 230.5 MiB. This supports
  real improvement beyond the 256-clip development subset, but remains below
  the neural baseline. Source fingerprint is saved with the evaluation.
- R5 rejected: whole-clip consensus 70/256 corrected, 68/256 uncorrected.
- R6 training-only motion-compensation probe: align adjacent frames with sparse
  optical flow and a robust partial-affine transform; retain newly brightened
  pixels before colour extraction. Uncorrected 104/256; endpoint extension
  0.02 gives **125/256 (48.83%)**, with improved endpoint/duration counts.
- Additional training probes: alignment of component long axis with movement
  yields only 107/256 on the old method (versus 105/256). Replacing inferred
  duration with a fixed-onset estimate harms recovery (best 95/256); reject it.
  These probes are in ignored `tmp/classical-model-1/`, not final-test results.
