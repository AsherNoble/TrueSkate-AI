/b# Trick Library Format Reference

This document describes the JSON format used for trick libraries and recipe files in TrueSkate-AI.

## Overview

A trick library file contains a single learned trick recipe, with both "best" and "median" variants. These files are generated by `scripts/build_trick_library.py` from CMA-ES optimization logs and can be replayed on-device via `scripts/inspect/execute_trick.py`.

## File Structure

```json
{
  "trick": "360 FLIP",
  "median_gestures": { ... },
  "best_gestures": { ... }
}
```

### Top-level Fields

- **`trick`** (string): Canonical trick name, e.g. `"360 FLIP"`, `"VARIAL KICKFLIP"`
- **`median_gestures`** (object): Recipe using median parameters across converged evaluations
- **`best_gestures`** (object): Recipe using best (highest-reward) parameters across evaluations

### Gesture Recipe Structure

Each recipe (`median_gestures` or `best_gestures`) has this format:

```json
{
  "gestures": [
    {
      "points": [[x0, y0], [x1, y1], [x2, y2]],
      "duration": 0.35,
      "easing_power": 1.5
    },
    {
      "points": [[x0, y0], [x1, y1], [x2, y2]],
      "duration": 0.40,
      "easing_power": 0.8
    }
  ],
  "delays": [0.12]
}
```

#### `gestures` Array

A list of 1 or more gesture objects. Most tricks use 2–3 gestures (after the initial push). Each gesture:

- **`points`** (array of [x, y] pairs): Normalized waypoints in the range [0.0, 1.0]. Normalized to device logical coordinates at playback time based on device resolution.
  - Typical 3-point path: start → control point → end
  - Used to build smooth curved drags via Catmull-Rom interpolation

- **`duration`** (float): Total duration of this gesture in seconds, e.g., 0.35
  - Typical range: 0.03–0.8 seconds
  - Longer durations = slower, more deliberate motions

- **`easing_power`** (float): Controls velocity profile of the gesture
  - **< 1.0**: Decelerating (fast start, slow end) — good for downward/ending motions
  - **= 1.0**: Linear (constant velocity) — neutral
  - **> 1.0**: Accelerating (slow start, fast end) — good for flicking/quick finishes
  - Typical range: [0.3, 3.0]
  - Mathematically: `velocity ∝ t^easing_power` across [0, 1]

#### `delays` Array

A list of N-1 delays (for N gestures), each in seconds. Specifies the wait time after each gesture before starting the next.

For a 2-gesture recipe:
```json
"delays": [0.12]
```
Meaning: After gesture 0 completes, wait 0.12s, then fire gesture 1.

For a 3-gesture recipe:
```json
"delays": [0.12, 0.15]
```
Meaning: After gesture 0 wait 0.12s → gesture 1; after gesture 1 wait 0.15s → gesture 2.

## Example

```json
{
  "trick": "KICKFLIP",
  "median_gestures": {
    "gestures": [
      {
        "points": [[0.3, 0.5], [0.4, 0.4], [0.5, 0.35]],
        "duration": 0.25,
        "easing_power": 1.2
      },
      {
        "points": [[0.5, 0.3], [0.55, 0.2], [0.6, 0.15]],
        "duration": 0.30,
        "easing_power": 0.9
      }
    ],
    "delays": [0.10]
  },
  "best_gestures": {
    "gestures": [
      {
        "points": [[0.32, 0.52], [0.42, 0.42], [0.52, 0.37]],
        "duration": 0.26,
        "easing_power": 1.3
      },
      {
        "points": [[0.52, 0.32], [0.57, 0.22], [0.62, 0.17]],
        "duration": 0.31,
        "easing_power": 0.85
      }
    ],
    "delays": [0.11]
  }
}
```

## Execution Context

When a recipe is executed via `execute_trick.py`:

1. **Push phase**: A static upward push is performed first (duration ~0.3s, easing ~2.0)
2. **Recipe phase**: After push delay (~0.5s total), the gestures are executed in sequence:
   - Gesture 0 fires immediately
   - After gesture 0 + delay[0], gesture 1 fires
   - After gesture 1 + delay[1], gesture 2 fires (if present)
   - etc.
3. **Reset**: After the final gesture, the board is automatically reset to center position

## Coordinate System

- **Normalized coordinates**: All points in libraries are in [0.0, 1.0] range
- **Logical points**: At runtime, these are converted to device logical coordinates:
  - iPhone XS: 375×812
  - iPhone 11 / XR: 414×896
  - Conversion: `device_x = norm_x * device_width`, `device_y = norm_y * device_height`

## Tips for Manual Editing

- Points should form a smooth path; large jumps between waypoints create abrupt direction changes
- Easing power tunes **how** the gesture accelerates, not the distance traveled
- Delays should account for visual feedback and control feel; too short = overlapping motion; too long = unresponsive
- Test incrementally—small adjustments (±0.05 easing, ±0.02 duration) are usually sufficient
